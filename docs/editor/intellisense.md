# 补全、诊断与悬浮信息

这三个功能都由同一套 GML 语言服务驱动，目标是让反编译出来的代码像在现代 IDE 里一样可读、可改。

| 功能 | WPF | Avalonia |
|:--|:--:|:--:|
| 自动补全 | ✅ | ✅ |
| 实时语法诊断 | ✅ | ✅ |
| 参数数量检查 | ✅ | ❌ |
| 悬浮信息（函数/变量/常量） | ✅ | ✅ |
| 悬浮预览（精灵/数字/颜色） | ✅ | ✅ |

## 自动补全

### 用法

不需要按快捷键，也不需要在菜单里开启。在 **GML 反编译**页面输入时会自动弹出候选列表：

- 输入字母、数字或 `_`，且前一个字符是标识符字符时触发；
- 输入 `.` 触发成员补全；
- 行内 `//` 注释之后不触发；
- 只读标签页不触发；
- 没有 `Ctrl+Space` 手动触发。

候选列表会自动过滤，最多显示 320 像素高。候选项右侧会显示类型（函数、变量、资源等）。

### 候选来源

| 来源 | 例子 |
|:--|:--|
| 内置函数 | `draw_sprite`、`instance_create_layer` |
| 实例变量 / 全局变量 | `x`、`y`、`global.foo` |
| 常量 | `vk_left`、`c_white` |
| GMS 2.3+ 全局函数 | 当前数据文件中的函数表 |
| 2.3 之前的脚本名 | `scr_*` 脚本 |
| 资源名 | 对象、精灵、声音、背景、路径、房间、字体、时间线、着色器、动画曲线、序列、粒子系统 |
| 当前代码的局部变量 | `var` 声明的变量、参数 |
| GML 关键字 | `if`、`for`、`function` 等 |
| 当前文档中已出现的词 | 兜底候选 |

GmlSpec 文档中的函数、变量、常量也会进入候选。界面语言为中文时优先使用中文条目。

### 限制

- `.` 后的成员补全**不包含函数**，只补变量/字段；
- 候选会去重，同名条目保留优先级更高的一条；
- 补全不会修改代码，只是插入文本；插入后仍需编译（`Ctrl+K`）才会生效。

## 实时静态诊断

### 开启方式

WPF 有两级开关：

- **编辑菜单** → **自动检查错误**、**自动检查参数数量可能不匹配的函数**；
- 代码编辑器顶部的同名复选框。

Avalonia 只有编辑器顶部的 **自动检查错误** 复选框，**没有参数数量检查**。

默认均为开启。

### 行为

1. 停止输入约 600 ms 后，在后台线程解析当前代码；
2. 错误显示为红色点状波浪线 + 淡红色行背景；
3. 警告显示为蓝色点状波浪线 + 淡蓝色行背景；
4. 编辑器底部的结果面板列出 `行,列: 消息`；
5. 双击结果跳转到对应位置；
6. 可以手动关闭结果面板，关闭后仍会更新波浪线。

![实时诊断与参数检查](assets/img/diagnostics.png)

### 检查范围

- 只对 **GML 反编译**页生效；
- 只检查顶层代码条目（`ParentEntry == null`），子代码不检查；
- 参数数量检查会跳过可变参数函数（签名含 `...`）和 `a.b(...)` 这类成员调用；
- 解析上下文构建失败时不会产生诊断，也不会报错。

诊断是静态分析，不等于 GameMaker 编译器的完整校验。最终能否运行仍以编译和 Butterscotch/官方 runner 为准。

## 悬浮信息

### 开启方式

| 前端 | 开关 |
|:--|:--|
| WPF | **编辑菜单 → 悬浮信息**，或编辑器顶部复选框 |
| Avalonia | 编辑器顶部复选框 |

默认开启。设置保存在 `settings.json` 的 `CodeEditorShowHoverInfo`。

### 触发方式

把鼠标停在代码上约 **250 ms**。移动、滚动、点击或移出编辑器都会关闭面板。

WPF 的悬浮面板允许点击穿透，因此可以直接在文档上右键或跳转；Avalonia 任意按下、滚动或点击都会关闭面板。

### 能显示什么

#### 函数、变量、常量

- **函数**：签名（参数名与类型，可选参数用 `[]` 表示）、返回类型、说明、逐参数说明；
- **变量**：类型、是否可读写、说明；
- **常量**：类别、类型、说明。

文档来自内置的 `GmlSpec` 数据：

- 中文界面优先 `GmlSpecChinese.gmlspec`；
- 缺失条目回退到英文 `GmlSpecEnglish.gmlspec`；
- 没有 GmlSpec 条目时，至少显示“内置函数/变量/常量”标签。

WPF 还会显示反编译阶段推断出的信息，例如整型实参对应的资源类型、函数参数类型推断。

![内置函数悬浮文档](assets/img/hover-builtin-doc.png)

![英文界面下的悬浮文档](assets/img/hover-builtin-doc-en.png)

#### 数字字面量

把鼠标停在数字上，会按 ID 列出可能的资源：

- 精灵、房间、对象、背景、脚本、路径、字体、声音、着色器、时间线、动画曲线、序列、粒子系统；
- 精灵会显示缩略图；
- 大于 `0x50000` 的数字会显示颜色块；
- 命中内置常量时显示常量名；
- 最后一行显示 `id (数字)`。

![数字字面量的资源预览](assets/img/hover-number.png)

#### 标识符 / 资源名

停在资源名上会显示：

- 资源类型与资源 ID；
- 精灵的 128px 预览；
- 对应资源的悬浮信息。

![精灵悬浮预览](assets/img/hover-sprite.png)

### 限制

- 依赖语法高亮的段名（`Number` / `Identifier` / `Function`）。如果高亮没有产生这些段，就不会弹出；
- 数字没有命中任何资源或常量时不弹；
- 悬浮文档是离线数据，不会联网查询；
- 反汇编页也挂了悬浮事件，但能否产生有意义的内容取决于 VMASM 高亮段，实际以界面为准。
