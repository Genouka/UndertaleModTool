# 标签页分离与修改跟踪

## 标签页分离为窗口（仅 WPF）

WPF 版可以把标签页“撕”成独立窗口，方便同时对照多个资源。

### 分离

两种方式：

1. **右键标签标题** → **分离到新窗口**；
2. 按住左键拖动标签标题，水平移动超过 2 像素后，把指针拖到主窗口标签条之外。

结果：

- 新建一个居中的独立 `TabWindow`；
- 原标签从主窗口移除；
- 如果主窗口已无标签，会自动打开“欢迎”说明页。

### 还原

- 把标签从子窗口拖回主窗口标签条；
- 或拖到另一个子窗口；
- 或直接关闭子窗口：其中的标签会进入主窗口的“已关闭标签历史”，可用 **Ctrl+Shift+T** 恢复。

分离/还原会保存和恢复标签内容状态（例如滚动位置）。

### 限制

- **AutoClose 标签不能分离**：说明页、欢迎页等自动关闭标签右键无效，拖拽时如果只剩一个 AutoClose 标签也会被阻止；
- 只有 WPF 支持；Avalonia 标签右键只有“在列表中选中 / 关闭 / 关闭所有标签页”；
- 多行标签设置（`TabMultiLine`，滚轮向下切换）同样作用于分离窗口。

## 数据修改跟踪

修改跟踪用颜色标出“哪些内容被改过”，避免保存前忘记检查。

### WPF

总开关：**设置 → 追踪代码更改**，默认开启。

| 位置 | 表现 |
|:--|:--|
| 资源树 | 已修改资源显示**橙色前景** `#FF9800` |
| 代码编辑器 | 与原始反编译文本做行级 diff，改动行加**橙色半透明背景** |
| 代码条目 | 失焦编译后比较字节码快照，决定是否标记 |

清除方式：

- 成功保存文件后全部清除；
- 关闭“追踪代码更改”会清空并刷新资源树；
- 代码条目字节码恢复原样时自动取消标记；
- 没有独立的“清除修改标记”菜单命令。

跟踪粒度：

- 资源级：任意 `INotifyPropertyChanged` 属性变化、集合增删都会标记（对象级，不区分具体属性）；
- 代码级：以编译后的字节码快照为准，而不是单纯文本 diff。

### Avalonia

- 代码编辑器有同样的行级 diff 和橙色高亮；
- **没有资源树高亮**；
- 设置文件中存在 `ChangeTrackingEnabled`，但设置窗口没有对应开关；
- 保存或重新反编译后重置原始文本。
