# 批量图片导入

把一整个文件夹的 PNG/GIF 按命名规则批量导入游戏，自动创建或替换精灵、背景和字体贴图，并按需重排纹理页。

> **仅 WPF 版支持。** Avalonia 当前没有“导入图像”菜单。

## 入口

`文件 → 导入图像...`

当前必须已经打开一个数据文件。

## 文件夹与命名规则

导入器会递归扫描所选文件夹中的 `.png` 和 `.gif`，根据**文件所在文件夹名**判断资源类型：

| 文件夹名（不区分大小写） | 类型 | 处理方式 |
|:--|:--|:--|
| `sprites` / `sprite` | 精灵 | 按帧导入 |
| `backgrounds` / `background` | 背景 | 文件名即背景名 |
| `fonts` / `font` | 字体 | 作为字体贴图 |
| 其他名称 | 未知 | 默认跳过；勾选“将未知类型的图像作为精灵导入”后按精灵处理 |

> 推荐目录结构：
>
> ```
> import/
>   sprites/
>     spr_player_0.png
>     spr_player_1.png
>   backgrounds/
>     bg_forest.png
>   fonts/
>     fnt_dialog.png
> ```

### 精灵/背景文件名

| 文件名 | 含义 |
|:--|:--|
| `name.png` | 精灵第 0 帧，或背景 `name` |
| `name_0.png`、`name_1.png` | 精灵 `name` 的第 0、1 帧 |
| `name_strip4.png` | 把图片水平切成 4 帧，宽度必须能被 4 整除 |
| `name.gif` | 按 GIF 帧拆分为精灵 `name` 的多帧 |
| `name_1.png`（没有 `_0`） | 判定为从 1 开始编号，整体减 1 |

同名文件重复会被视为错误。帧号超出已有精灵帧数时，状态显示“帧超出范围”。

## 操作步骤

1. 打开数据文件；
2. 选择 `文件 → 导入图像...`；
3. 点击“浏览...”选择导入文件夹；
4. 点击 **扫描**；
5. 在表格中确认每张图的类型、精灵名、帧号、尺寸、状态和纹理页；
6. 按需修改每张图的“模式”，或用上方的“全局设置”批量应用；
7. 点击 **确定**；
8. 等待导入进度条完成。

![批量图片导入对话框](assets/img/batch-image-import.png)

## 导入模式

每张图可以单独选择模式：

| 模式 | 适用对象 | 行为 |
|:--|:--|:--|
| **原位替换** | 已存在的精灵 | 直接替换纹理页项，要求图像尺寸与原始尺寸完全一致 |
| **新建纹理页** | 任意图片、新精灵、背景、GIF、精灵条 | 用纹理打包器创建新纹理页；支持任意尺寸 |
| **保持原纹理页** | 已存在的精灵 | 尺寸一致时原位替换；新图更小时其他项位置不变；新图更大时重排该纹理页 |

新建精灵没有“原纹理页”，因此只能使用“新建纹理页”。

默认模式由每张图的扫描结果决定：

- 已存在且尺寸匹配 → 保持原纹理页；
- 否则 → 新建纹理页。

上方的“默认导入模式”和 **应用到选中项** 可以批量修改。

## 全局设置

| 设置 | 默认值 | 说明 |
|:--|:--|:--|
| 将未知类型的图像作为精灵导入 | 开 | 文件夹名无法判断类型时按精灵处理 |
| 原点位置 | 左上 | 9 个位置：左上/上中/右上/左中/居中/右中/左下/下中/右下 |
| 动画速度 | 1 | 新建精灵的播放速度 |
| 播放类型 | 每游戏帧数 | 每秒帧数 / 每游戏帧数 |
| 特殊类型 | 关 | GMS2 精灵特殊类型 |
| 特殊版本 | 1 | 特殊类型版本号 |
| 纹理页大小 | 2048 | 2048 / 4096 / 8192 |

GMS1 数据文件会禁用“特殊类型”“动画速度”“播放类型”“特殊版本”，这些字段不适用。

## 状态列说明

| 状态 | 含义 |
|:--|:--|
| 可以替换 | 已存在且尺寸完全匹配，可原位替换 |
| 尺寸不匹配 | 已存在但尺寸不同；可改用新建/保持原纹理页 |
| 帧超出范围 | 已有精灵没有对应帧号 |
| 新精灵 / 新背景 | 目标中不存在，将创建 |
| 目标文件中已存在 | 背景/精灵已存在 |

## 行为细节

- 非背景图片会先加 1px 透明边、计算包围盒、裁剪，并把 `TargetX/TargetY` 设为裁剪偏移；
- 精灵/背景导入后会标记为项目导出资产（如果启用了项目）；
- “新建纹理页”模式会在程序目录下生成 `Packager/atlas.txt`、`atlas*.png` 和 `.log` 调试文件；
- 逐项导入会先把图片复制到临时目录，再统一打包；
- 超过纹理页尺寸的图片会被打包器跳过。

## 常见问题

| 现象 | 处理 |
|:--|:--|
| 扫描后列表为空 | 确认文件夹中有 PNG/GIF；未知类型需勾选“作为精灵导入” |
| “尺寸不匹配” | 改用“新建纹理页”，或先把图片调整为原始尺寸 |
| “原位替换”失败且提示已有部分精灵被修改 | 这是批量导入的中途失败；建议备份后改用“新建纹理页”重试 |
| 导入后精灵位置偏移 | 检查原点设置；图片裁剪会改变 `TargetX/Y` |
| 纹理页过大/过多 | 选择 4096 或 8192，或在导入后使用[纹理页迁移](docs/tools/texture-migration.md)整理 |
| GIF 只导入了部分帧 | 确认 GIF 帧数完整，且精灵帧号没有冲突 |

## 限制

- 不支持缩放比例、旋转或九宫格设置；
- 字体贴图按普通纹理导入，字形数据仍需在字体编辑器中检查；
- 不校验 GML 代码中的引用；
- 导入修改只在内存中，保存数据文件后才生效。
