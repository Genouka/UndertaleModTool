# 从其他数据文件导入

把一个游戏里的资源搬到另一个游戏，而不必先导出再导入。适用于整合 mod、复用素材、把测试资源迁移到正式工程。

> **仅 WPF 版支持。** Avalonia 当前没有“从文件导入”菜单。

## 入口

`文件 → 从文件导入...`

当前必须已经打开一个数据文件；否则菜单项不可用。

## 操作步骤

1. 打开**目标**数据文件（要接收资源的游戏）；
2. 选择 `文件 → 从文件导入...`；
3. 在 **源数据文件** 中点击“浏览...”，选择另一个 `data.win` / `.unx` / `.droid` / `.wad`；
4. 选择 **名称冲突处理**；
5. 决定是否勾选 **自动包含依赖项**；
6. 在左侧“可用资源”中搜索、勾选要导入的资源，双击或拖到右侧；
7. 点击 **导入**；
8. 等待加载和导入完成，查看摘要、警告与错误。

## 选项说明

### 名称冲突处理

| 选项 | 行为 |
|:--|:--|
| 跳过已存在的 | 默认。目标中已有同名资源时保留目标版本，计入“已跳过” |
| 覆盖已存在的 | 用源资源替换目标中的同名资源，计入“已覆盖” |
| 重命名导入的 | 生成不冲突的新名称后导入 |

> 冲突检测覆盖声音、精灵、背景、路径、脚本、字体、游戏对象、房间、动画曲线和序列。着色器、时间线、扩展、粒子系统等没有统一的存在性判断，可能不会出现在“目标文件中已存在”的提示里。

### 自动包含依赖项

默认开启。选中一个资源时，导入器会尝试把它的依赖一起带入，例如：

- 对象 → 精灵、父对象、碰撞对象；
- 房间 → 房间中的对象、背景等；
- 脚本/对象事件 → 被引用的代码；
- 精灵/字体 → 纹理页项。

依赖关系无法解析时会记录警告，而不会中断整个导入。

### 资源选择

- 左侧列表支持按名称过滤；
- 双击在两栏之间移动；
- 支持多选、全选、取消全选；
- 右侧显示最终要导入的资源；
- 已存在的资源会显示“目标文件中已存在”。

## 支持的资源类型

| 类型 | 说明 |
|:--|:--|
| 声音 | 含音频数据与音频组设置 |
| 精灵 | 含纹理页项、帧、遮罩等 |
| 背景 | 含纹理页项 |
| 路径 | 路径点 |
| 脚本 | 脚本与代码条目 |
| 着色器 | 着色器元数据与源码（取决于能否项目序列化） |
| 字体 | 字形、纹理页项 |
| 时间线 | 时间线事件 |
| 游戏对象 | 事件、父对象、碰撞、物理属性等 |
| 房间 | 层、实例、瓦片、创建代码等 |
| 扩展 | 扩展定义 |
| 动画曲线 | 曲线通道与关键帧 |
| 序列 | 序列轨道与关键帧 |
| 粒子系统 | 粒子系统定义 |

导入基于 **项目序列化**。如果某个资源没有实现 `IProjectAsset`，或标记为不可导出，会被跳过并在警告中说明。这不是“复制二进制块”，目标数据文件的版本和结构必须兼容。

## 结果与警告

导入完成后会显示汇总：

- 已导入数量；
- 已跳过数量；
- 已覆盖数量；
- 警告与错误列表（最多显示一部分，超出显示“...还有 N 条”）。

常见警告：

| 警告 | 含义 |
|:--|:--|
| `does not support project serialization and was skipped` | 该资源类型不支持项目序列化 |
| `is not exportable and was skipped` | 资源本身不可导出（例如外部引用） |
| 依赖缺失 | 父对象/精灵/声音等未在源或目标中找到 |
| 纹理/音频格式不支持 | 需要先转换格式 |

## 限制与注意事项

- **先备份目标文件**。导入会直接修改当前内存中的数据，保存后才落盘；
- 源文件必须是工具能读取的 GameMaker 数据文件；不兼容的版本可能加载失败；
- 导入不会自动修复目标中的引用冲突；重名资源建议先用“重命名导入的”；
- 大型游戏导入可能占用大量内存，建议分批导入；
- 导入后的资源会标记为项目导出资产（如果启用了项目）；
- 纹理页尺寸、音频组等运行参数可能需要在导入后手动检查；
- 保存前可以用“数据修改跟踪”查看哪些资源被改过（WPF）。
