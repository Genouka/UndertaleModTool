# Butterscotch 运行与调试

Butterscotch 是一个用 C 实现的 GameMaker 字节码解释器。本分支把它以 `bsdbg` 原生库的形式嵌进 UndertaleModTool，让你不必导出游戏，就能直接运行当前打开的数据文件，并在 WPF 版中逐指令调试。

> 这是本分支最“重”的功能，也是限制最多的功能。开始前请先读[能力边界](docs/runtime/butterscotch.md?id=capabilities)，避免把“能加载”误认为“能完整通关”。

<a id="capabilities"></a>

## 能力边界

Butterscotch 不是 GameMaker 官方 runner 的替代品。根据其上游说明和本仓库的集成方式：

| 项目 | 支持情况 |
|:--|:--|
| WAD 版本 8–17 | 支持（GM:S 1.0.198+ 到 GMS 2.2+） |
| 解释执行的 GML | 支持 |
| YYC 原生编译的游戏 | **不支持** |
| GMRT VM | **不支持** |
| pre-WAD8（原始 GML 解释执行） | **不支持** |
| 依赖外部扩展（Discord、部分着色器扩展等） | 可能失败 |
| 音频 | 仅实现 FMOD 路径 |

字节码兼容性仍在完善中，同一个游戏可能出现原版 runner 没有的怪癖。**运行前务必备份数据文件**，并优先在副本上测试。

## 准备

### 1. 原生库

内置运行器需要与进程架构匹配的 `bsdbg` 原生库：

| 平台 | 需要的文件 | 获取方式 |
|:--|:--|:--|
| Windows x64 | `native\win-x64\bsdbg.dll` | 发布包自带；源码构建时由 MSBuild 自动调用 `tools/build-bsdbg.ps1` |
| Windows x86 | `native\win-x86\bsdbg.dll` | 同上 |
| Linux | `native/linux-<arch>/libbsdbg.so` | 需自行用 `tools/build-bsdbg.sh --backend sdl2` 构建 |
| macOS | `native/osx-<arch>/libbsdbg.dylib` | 需自行构建 |
| Android | APK 内 `lib/<abi>/libbsdbg.so` | 仓库已带 arm64 与 x64 版本，随 APK 打包 |

Windows 发布包已经包含 x64/x86 的 DLL。Linux/macOS 的官方 nightly 包**不保证**包含原生库；如果启动时提示内置运行器不可用，请按上面的脚本自行构建，或改用外部运行器。

### 2. 保存数据文件

Butterscotch 运行的是磁盘上的数据文件，不是内存中的未保存修改。因此：

- **WPF**：按 F6 / Shift+F6 后会先执行一次保存（有工程时保存到工程的 `SaveDataPath`，否则弹出“另存为”）。取消保存就不会启动。
- **Avalonia**：会询问“运行前是否保存数据文件？”。选“是”保存并继续，选“否”直接使用磁盘上的旧文件，选“取消”中止。

### 3. 打开 Butterscotch 菜单

WPF 默认显示；Avalonia 桌面端默认显示，**Android 默认隐藏**。如果“文件”菜单里没有相关条目：

1. 打开 **设置**；
2. 勾选 **显示 Butterscotch 调试选项**；
3. 关闭设置窗口后菜单立即刷新。

## 运行游戏

| 前端 | 运行 | 调试 |
|:--|:--|:--|
| WPF | `文件 → 使用 Butterscotch 运行`，或 **F6** | `文件 → 使用 Butterscotch 调试`，或 **Shift+F6** |
| Avalonia 桌面 | `文件 → 使用 Butterscotch 运行`，或 **F6** | `文件 → 使用 Butterscotch 调试`，或 **Shift+F6** |
| Avalonia Android | 同上（需先在设置中打开菜单） | 同上 |

“运行”从游戏入口正常开始；“调试”会在第一帧的第一条指令处暂停（Stop on entry）。

## 选择运行器架构

打开 **设置 → Butterscotch 运行器**，有四个选项：

| 选项 | 行为 | 能否调试 |
|:--|:--|:--:|
| 内置调试器（当前进程） | 在当前进程内加载 `bsdbg`，游戏画面由编辑器承载 | ✅ |
| x64（外部进程） | 启动独立的 64 位 `butterscotch.exe` | ❌ |
| x86（外部进程） | 启动独立的 32 位 `butterscotch.exe` | ❌ |
| ARM64（外部进程） | 启动独立的 ARM64 `butterscotch.exe` | ❌ |

- **只有“内置调试器”支持断点和单步。** 选择外部架构后按 Shift+F6 会提示“只有内置 Butterscotch 调试器支持调试”。
- **Butterscotch 可执行文件**可以留空。留空时会在应用目录、`native\win-<arch>`、`butterscotch\win-<arch>`、`butterscotch` 以及游戏目录中按架构查找候选可执行文件。
- 外部模式只支持 Windows PE 可执行文件；在 Linux/macOS/Android 上请使用内置模式。

## WPF 调试器

启动调试后，主窗口会自动打开非模态的 **Butterscotch 调试面板**。关闭面板不会结束会话，可以从菜单重新打开。

### 调试面板

面板顶部显示状态：

- 灰色：没有调试会话；
- 绿色：运行中，显示帧号；
- 黄色：已暂停，显示帧号以及当前代码名（停在帧边界时显示“帧边界”）。

“执行控制”区域：

| 按钮 | 作用 | 可用条件 |
|:--|:--|:--|
| 继续 | 从当前位置继续运行 | 已暂停 |
| 暂停 | 在下一指令处停下 | 运行中 |
| 逐语句 | 执行下一条 GML 指令 | 已暂停 |
| 逐过程 | 执行到当前调用帧的下一条指令或返回，不进入函数 | 已暂停 |
| 跳出 | 运行到当前调用帧返回 | 已暂停 |
| 单帧 | 推进一整帧后再次暂停 | 已暂停 |
| 停止 | 结束会话 | 随时 |
| 热重载 | 把当前代码条目的修改下发给运行中的游戏 | 活动且已暂停 |

“诊断窗口”区域可以打开断点、变量、实例、调用堆栈和输出窗口。

### 断点

断点只能设在**反汇编**视图：

1. 打开一个代码条目；
2. 切换到 **反汇编** 标签页；
3. 点击指令行左侧的边栏，出现红点即表示断点已设置；
4. 再次点击取消。

断点以“代码条目索引 + 字节码偏移”定位，因此注释、标签、`.localvar` 和空行不能设断点。断点可以在启动调试前设置，启动时会统一下发；运行中也可以增删。

### 停止行高亮

命中暂停后，编辑器会清空旧高亮，并在当前代码的反汇编视图中用黄色半透明背景标出停止指令，同时滚动到该行。只有反汇编标签页可见时才能看到高亮。

### 变量窗口

变量窗口列出当前调用帧的：

- **local**：局部变量；
- **argument[n]**：参数；
- **global**：全局变量。

双击“值”单元格可以编辑。支持的类型：

| 类型 | 输入示例 |
|:--|:--|
| real | `3.14` |
| int32 / int64 | `42` |
| bool | `true` / `false` / `1` / `0` |
| string | `hello` |
| undefined | `undefined` |

数组、结构体、方法和 asset 引用只读。写入操作要求会话处于暂停状态。

### 实例窗口

左表列出当前房间中的实例：ID、对象、X、Y、Depth。选中一个实例后，右表显示该实例的变量，双击值可以编辑。列表只在暂停时刷新；刷新后会尽量保持原选中项。

### 调用堆栈窗口

每一帧显示 `CodeName @ 0xIP`，以及 `self=…`、`event=…`。双击某一帧会激活主窗口并打开对应代码条目的反汇编视图。

### 输出窗口

显示会话日志：`[debug|info|warn|error]` 前缀的消息、暂停/退出/热重载事件和错误。最多保留 2000 行，支持右键复制、复制全部和清空。

### 热重载

热重载只针对**当前打开的代码条目**：

1. 在编辑器中修改 GML 并应用（编译到当前代码条目）；
2. 暂停游戏；
3. 点击调试面板的 **热重载**。

限制：

- 当前标签页必须是代码条目，否则日志提示 `Open a code entry to hot reload it.`；
- 只下发代码字节码和字符串字面量；
- 对象、事件、房间、资源等数据修改**不会**被热重载，需要停止会话、保存并重新启动；
- 原生端会在帧边界或暂停时应用补丁。

### 诊断数据上限

为避免大游戏卡死调试器，原生端对诊断数据做了截断：

- 值嵌套深度 3 层；
- 每个值最多 200 项；
- 每个实例/全局最多 500 个变量；
- 调用栈最多 4096 帧。

超出部分会标记为 `truncated`。

## 设置项速查

| 设置 | 默认值 | 说明 |
|:--|:--|:--|
| 显示 Butterscotch 调试选项 | WPF：开；Avalonia 桌面：开；Android：关 | 控制“文件”菜单中的两个入口 |
| Butterscotch 运行器 | 内置调试器（当前进程） | 内置可调试，外部仅运行 |
| Butterscotch 可执行文件 | 空 | 留空自动探测 |

## 故障排查

| 现象 | 原因与处理 |
|:--|:--|
| “内置 Butterscotch 调试器需要…bsdbg.dll” | 缺少与进程架构匹配的原生库。检查 `native\win-x64` / `native\win-x86`，或改用外部运行器。 |
| “只有内置 Butterscotch 调试器支持调试” | 当前运行器是外部架构。切换到“内置调试器（当前进程）”，或改用“运行”。 |
| “运行 Butterscotch 前请先保存数据文件” | Avalonia 选择了“不保存”，但磁盘上的数据文件不存在。先保存一次。 |
| “已有一个外部 Butterscotch 实例在运行” | 关闭之前启动的外部进程，或结束残留的 `butterscotch.exe`。 |
| 启动后立刻退出 / 黑屏 | 游戏可能使用 YYC、GMRT、pre-WAD8 或不支持的扩展。先用官方 runner 确认游戏可运行，再查看调试输出。 |
| 断点不生效 | 确认断点设在反汇编视图、位于真实指令上，并且当前是内置调试器。 |
| 热重载提示 “Open a code entry…” | 当前标签不是代码条目。切换到要热重载的代码条目再试。 |
| Linux/macOS 提示内置运行器不可用 | 发布包可能未包含 `libbsdbg`。用 `tools/build-bsdbg.sh --backend sdl2` 构建后放到 `native/<平台>-<架构>/`。 |
