# 代码分析与 GMRT

## 更准确的代码分析器

反编译器会在生成 GML 时做类型推断，把原本难以阅读的整数字面量展开成有意义的常量。例如：

```gml
// 展开前
if (state == 3) { ... }

// 展开后
if (state == obj_enemy_state_attack) { ... }
```

### 设置

打开 **设置 → GML 设置**，在“自动推断”下有三个开关：

| 开关 | 默认 | 作用 |
|:--|:--:|:--|
| 推断脚本参数类型 | 开 | 分析脚本中 `argument0` 等参数的流向，推断类型，并在调用处把整数字面量展开为枚举、资源、颜色等命名常量 |
| 反向推断变量类型 | 开 | 把推断出的参数类型反向传播到接收赋值的变量，使这些变量的字面量也能展开 |
| 内联传播变量类型 | 开 | 已知类型的参数赋给变量时，立即注册该变量类型，使后续赋值的字面量可以展开 |

“反向推断变量类型”依赖“推断脚本参数类型”；关闭后者时前者不会生效。

### 行为与限制

- 只影响反编译的**显示/清洁阶段**，不修改字节码；
- 推断不确定时会生成 `UnknownEnum` / `Value_{n}` 之类的占位声明；
- 对动态类型、复杂控制流、反射式访问的推断可能不准确；
- 关闭推断可以得到更“原始”的反编译结果，便于对照字节码；
- 设置只影响之后重新反编译的代码；已打开的代码条目需要重新加载/反编译。

### 与实时诊断的区别

| 功能 | 位置 | 作用 |
|:--|:--|:--|
| 代码分析器 | 反编译阶段 | 改善输出可读性，展开常量 |
| 实时诊断 | 编辑器输入时 | 标出语法错误、参数数量不匹配 |
| 悬浮信息 | 鼠标悬停 | 显示函数/变量/常量文档与资源预览 |

## GMRT VM 与 `.wad`

GameMaker Runtime（GMRT）使用 `.wad` 资源包。本分支可以打开 `.wad`，但它走的是**独立的 WAD 编辑器**，不是 `data.win` 流程。

### 打开方式

- `文件 → 打开` 选择 `.wad`；
- 或把 `.wad` 拖进主窗口；
- 或通过命令行/文件关联打开。

打开后会弹出独立的 **WAD 编辑器窗口**，不会加载到主数据文件管线。

### 能做什么

| 功能 | 说明 |
|:--|:--|
| 文件信息 / 块表 | 查看 FORM 结构、`PRJT`、`RREF` 等块 |
| 条目预览 | 查看资源条目与绝对偏移 |
| 专用编辑器 | 精灵、声音、背景、房间、对象、序列、着色器、纹理、路径、时间线、字体 |
| 有限编辑 | 对象、字体（部分）、精灵、声音等可改固定尺寸字段 |
| 只读 | 背景、房间、路径、序列等标注为只读 |
| 保存 | 生成最小字节补丁，自动保留 `*.bak` |

### 限制

- `.wad` 使用 16 字节头、`PRJT`/`RREF` 块和绝对文件偏移，与普通 `data.win` 不同；
- 只能修改固定尺寸字段；帧数据、事件、blob 等变长区域不会被保存；
- 没有撤销；保存会原地改写并覆盖同名 `.bak`；
- **不是 GMRT VM 的反编译或运行支持**：不能反编译 GMRT 字节码，也不能用 Butterscotch 运行 GMRT 游戏；
- Underanalyzer 明确不包含 GMRT；
- 只支持 WPF 的 WAD 编辑器；Avalonia 没有 WAD 处理代码（文件过滤器里可能出现 `.wad`，但行为未验证）。

> 如果你要修改普通 GameMaker 游戏，请打开 `data.win`，不要使用 WAD 编辑器。

## 性能与内存优化

本分支对加载、反编译、编辑和渲染做了多处优化，没有单独的“性能”设置页。

### WPF

| 优化 | 效果 |
|:--|:--|
| 资源树刷新去抖 300ms | 批量修改时减少 UI 重绘 |
| 资源树搜索去抖 250ms | 输入搜索时不卡顿 |
| 资源树/DataGrid 虚拟化 + 回收 | 大资源列表滚动更流畅 |
| 图片解码缓存 | 纹理页/图块只解码一次；可选 `ArrayPool` 复用缓冲 |
| LOH 压缩 | 加载/保存后压缩大对象堆，降低内存峰值 |
| 后台反编译/编译 | 不阻塞 UI 线程；编辑失焦后台编译 |
| 诊断取消/代次校验 | 快速输入时取消过期分析 |
| 补全基列表缓存 | 按 `UndertaleData` 缓存，避免重复构建 |

### Avalonia

| 优化 | 效果 |
|:--|:--|
| `ImageCache` | 纹理页最多解码一次；后台解码；`WeakReference` 裁剪；并发上限 `clamp(CPU-1, 1, 4)` |
| `TaskQueue` | 后台任务串行调度，避免 UI 线程阻塞 |
| TreeDataGrid/DataGrid 虚拟化 | 大列表滚动 |
| 代码编辑器字号/捏合缩放 | 触摸端可调整字号 |
| 诊断防抖 | 与 WPF 相同的 600ms 防抖 |

### 用户能做什么

- 大游戏优先使用 x64 版本；
- 不要一次性打开过多大型纹理页；
- 批量导入/合并纹理页后，保存并重启应用释放内存；
- 关闭不需要的实时诊断/悬浮信息可减少编辑开销；
- 反编译大脚本时等待完成，避免连续切换标签页。
